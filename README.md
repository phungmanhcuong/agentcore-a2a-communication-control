# AgentCore A2A communication control

Nine agents on Amazon Bedrock AgentCore that may call each other over A2A only where one config file allows it: deny by
default, checked in the app and in AWS. Python 3.13 with Strands, one AgentCore runtime per agent, Terraform for AWS.
State of 2026-10-10. This repo holds only the A2A communication control part of a larger project; the model selection and
the 30-process scale run are left out.

## Who may call whom

`team.yaml` holds the rules:

```yaml
a2a:
  # How an agent proves who it is to a peer. none = local only; sigv4 = AgentCore with IAM; bearer = AgentCore with a JWT authorizer.
  auth: sigv4
  # Deny by default. A call is allowed only if a rule matches. Each side is an agent name or "role:<role>".
  # Who may start a task (the external caller "user"). On AWS this is the test invoker role, on the entry agents only.
  entry: ["role:planner"]
  allow:
    - {from: "role:planner", to: "role:worker"}
    - {from: "role:worker", to: "role:reviewer"}
    - {from: planner-1, to: reviewer-1}
```

With 3 planners, 3 workers and 3 reviewers this allows 19 of the 72 ordered agent pairs: 9 planner -> worker,
9 worker -> reviewer and planner-1 -> reviewer-1. Reviewers call no one and no rule points back, so calls cannot loop.
Python (`src/act_teams/policy.py`) and Terraform (`infra/locals.tf`) read the same file and expand it the same way:
`tests/test_policy.py` checks the Python pairs against the expected table and `tests/test_infra.py` checks that Terraform
gives the same pairs. Adding an agent or a rule is a `team.yaml` edit only.

## Where a call is checked

Any one checkpoint stops a call that the rules do not allow.

| # | Control | Side | What it stops | Code |
|---|---|---|---|---|
| 1 | Tool scoping | caller | The model gets an `ask_peer` tool only for its allowed peers; an agent with none has no such tool | `src/act_teams/server.py` (`build_agent`), `src/act_teams/a2a_client.py` (`make_ask_peer_tool`) |
| 2 | Per-agent peer map | caller | Each agent can read only its own map of its allowed peers' addresses (`peers/<agent>.json` in S3) | `infra/storage.tf`, `infra/iam.tf`, `server.py` (`load_peers`) |
| 3 | Client allow check | caller | A disallowed call raises `A2ADenied` before any network call | `a2a_client.py` (`A2AClient.send`) |
| 4 | SigV4 identity | caller | Every call is signed with the caller's own execution role | `a2a_client.py` (`SigV4Auth`) |
| 5 | IAM invoke policy (AWS layer 1) | caller | A role may invoke only the runtimes of its allowed peers | `infra/iam.tf` |
| 6 | Runtime resource policy (AWS layer 2) | callee | Allows the listed callers' roles; explicit Deny for every other principal | `infra/resource_policy.tf` |
| 7 | Header allow-list | callee | The runtime passes only `X-Act-Caller` and `X-Act-Token` through to the agent | `infra/locals.tf`, `infra/runtimes.tf` |
| 8 | Run token | callee | Callers without this deployment's token (generated by Terraform, kept in Secrets Manager) | `server.py` (`allow_check`, `resolve_run_token`), `infra/storage.tf` |
| 9 | Caller check | callee | A named caller that may not call this agent | `server.py` (`allow_check`) |
| 10 | Error containment | caller | A refusal reaches the model as a short `DENIED:` or `ERROR:` text; the agent keeps running | `a2a_client.py` (`ask_peer`) |
| 11 | Spend cap | both | Model requests once the cap is reached ($1 per runtime on AWS, $2 per local run) | `src/act_teams/spend.py`, `infra/variables.tf` |
| 12 | Time limits | both | Hung peers and runaway sessions: 300 s per peer call; a session ends after 300 s idle, 900 s at most | `a2a_client.py`, `team.yaml` (`runtime`) |

An app refusal is JSON-RPC error `-32003` in an HTTP 200 body, because AgentCore replaces any non-2xx answer from the
agent with HTTP 424.

## Known limits

* The caller header is a claim, not a signature. AWS layers 1 and 2 bind the real identity (the IAM role); the app checks
  the run token and the rules.
* AWS layer 2 does not stop the account root user (measured below). Every real caller must be an IAM role.
* The run token is shared by the whole team: it proves membership, not which agent is calling. Its value is in Terraform
  state and in the secret.

## Results (2026-10-10)

Local, no AWS (every round with its counts: `docs/TESTING.md`):

* 108 tests passed, including 10 live tests with real models (9 agents as local processes).
* 29 of 29 mutants killed: each control is broken on purpose in a scratch copy and a named test must fail
  (`scripts/mutants.sh`, output in `docs/results/mutants.txt`).
* Terraform: `fmt`, `validate` and `tflint` clean; checkov 61 passed, 0 failed, 10 skipped (each with a reason);
  `terraform test` with a mock provider, 5 passed on the rendered IAM and resource policies.

On AWS (AgentCore, us-east-1), deployed with an AWS CLI script (not in this repo) that creates the same roles and
policies, tested, then deleted. This Terraform was checked offline only; it was not applied that day.

| Test | Result |
|---|---|
| IAM policy simulator, all 72 ordered pairs | 19 allowed, 53 denied, 0 different from `team.yaml` |
| A task through planner-1 -> worker-1 | correct answer, 3 of 3 |
| A role that IAM lets invoke worker-1 but that is not a listed caller | 403 once the resource policy was applied, 2 of 2 |
| The account root user calling worker-1 | not stopped by the resource policy; only the app refused it, 3 of 3 |
| Run token: right token, no token, wrong token, right token with a spoofed caller | only the right token with an allowed caller got through, 5 of 5 |

## Run it

```
uv sync
uv run pytest -m "not live"                       # unit, static and offline Terraform-render tests
bash scripts/mutants.sh                           # break each control on purpose; the named test must fail
export OPENROUTER_API_KEY_FILE=/path/to/file      # a file that holds the key; never put the key on a command line
uv run pytest -m live                             # 9 local agent processes with real models, well under a cent
uv run python -m act_teams.local run              # start the team locally and send one task
```

Terraform, offline:

```
terraform -chdir=infra fmt -check && terraform -chdir=infra init -backend=false && terraform -chdir=infra validate
tflint --init --chdir infra && tflint --chdir infra; checkov -d infra; uv run python scripts/count_resources.py
scripts/tf_test.sh                                # `terraform test` (mock provider) on the rendered IAM and resource policies
```

Deploy (us-east-1; needs the permissions boundary and the invoker role named in `infra/variables.tf`):

1. `scripts/build_zip.sh` (aarch64 wheels for Python 3.13, zip < 250 MB).
2. `terraform -chdir=infra init -backend-config="path=<local state file>"`, then `plan`, review, `apply` with `AWS_PROFILE` set.
3. Put the OpenRouter key into the created secret out of band: `aws secretsmanager put-secret-value --secret-id <id> --secret-string file://<keyfile>`. Never in Terraform.
4. Test, then `terraform destroy`.

## Layout

* `team.yaml`: the one config (rules, roles, models, runtime limits).
* `src/act_teams/`: allow policy, A2A client, A2A server with the callee check, spend guard, model and tool setup, local runner.
* `infra/`: Terraform for the runtimes, IAM (layer 1), resource policies (layer 2), peer maps and secrets; `infra/tests/` holds the offline `terraform test` file.
* `tests/`: Python tests. `scripts/`: mutants, Terraform test and checks, zip build.
* `docs/PLAN.md`: the design, with AWS documentation quotes. `docs/TESTING.md`: every test round and its counts.
